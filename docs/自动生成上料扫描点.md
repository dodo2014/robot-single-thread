### 问题 1：如何保证所有点的 `r` 都与基座 X 轴垂直？

**你的思路是对的**：必须先调逆解算 $J1, J2$，再用 `calculate_j4_from_world_angle` 算 $J4$（即 JSON 里的 `r`）。

*   **物理含义**：与基座 X 轴垂直，意味着你的绝对世界角度 `World_R` 应该固定为 **-90°**（指向右侧）或 **90°**（指向左侧）。假设你希望相机 X 轴一直指向基座 Y- 方向，那 `World_R = -90`。
*   **因为每个点 $(X, Y)$ 的位置不同，大臂和小臂的角度 $(J1, J2)$ 必然不同**。为了保证 $J1 + J2 + J4 = -90^\circ$ 永远成立，每个点的 $J4$ (`r`) 必须是单独计算出来的、各不相同的数值，**绝不能全部填一样的 -90**。

### 问题 2：前两个 `elbow_up`，后三个 `elbow_down`，直接传参可以吗？

**完全可以，而且必须这么做！**

这在机器人学中叫做**“奇异点规避”**或**“干涉规避”**。
*   当你传 `elbow_up` 给 `inverse_kinematics_v2` 时，它会算出一种 $J1, J2$ 组合（肘部向左弯）。
*   当你传 `elbow_down` 时，它会算出另一种完全不同的 $J1, J2$ 组合（肘部向右弯）。
*   因为这两种姿态的 $(J1+J2)$ 之和相差极大，所以最终算出来的 $J4$ (`r`) 也会有天壤之别（通常差 100 多度）。

**你的 `config.json` 必须把这个 `config` 明确写进去**，否则控制器在运行时不知道你要用什么姿态，会导致撞机。

### 🎁 赠品：自动生成 35 个点 JSON 配置的 Python 脚本

因为你要算 35 个点，手动算太容易出错了。作为一个计算机工程师，写个脚本批量生成 JSON 是最优雅的做法。

你可以新建一个单独的 Python 脚本（比如 `generate_points.py`），直接运行它，把打印出来的结果复制粘贴到你的 `config.json` 里。

```python
import math
# 这里导入你现成的逆解函数，确保路径正确
from src.core.kinematics import ScaraKinematics 

def generate_search_points():
    # === 1. 填入你的机器人参数 ===
    l1 = 850.0
    l2 = 650.0
    z0 = 0.0
    nn3 = 0.05
    
    # 目标世界绝对角度 (与X轴垂直，假设朝向右侧为 -90度)
    TARGET_WORLD_R = -90.0  
    
    # 假设这5个列的 X 坐标 (你需要根据实际料架尺寸修改)
    col_x_list =[1500, 1400, 1300, 1200, 1100] 
    
    # 固定的 Y 坐标 (根据上一轮确定的黄金抓取 Y)
    FIXED_Y = 680.0
    
    # 层高参数
    top_z = 440.0
    layer_gap = 177.0 # 147(物料) + 30(木条)
    total_layers = 7
    
    search_points =[]
    
    # === 2. 嵌套循环生成 35 个点 ===
    for layer in range(total_layers):
        current_z = top_z - (layer * layer_gap)
        
        for col, x in enumerate(col_x_list):
            # 【核心逻辑】：前两个 up，后三个 down
            # 列索引 col: 0, 1 (前两个) -> elbow_up
            # 列索引 col: 2, 3, 4 (后三个) -> elbow_down
            elbow_cfg = "elbow_up" if col < 2 else "elbow_down"
            
            # 1. 调用逆解算 J1, J2 (传入指定的 elbow_cfg)
            ik_res = ScaraKinematics.inverse_kinematics_v2(
                x, FIXED_Y, current_z, 0,  # 这里的 te=0 不重要
                l1, l2, z0, nn3, 
                config_type=elbow_cfg
            )
            
            if not ik_res:
                print(f"警告: 点 L{layer+1}_C{col+1} (X={x}, Y={FIXED_Y}) 无法到达！")
                continue
                
            j1 = ik_res['the1']
            j2 = ik_res['the2']
            
            # 2. 反算 J4 (电机r) 以保持绝对角度
            j4 = TARGET_WORLD_R - (j1 + j2)
            
            # 归一化[-180, 180)
            while j4 > 180: j4 -= 360
            while j4 <= -180: j4 += 360
            
            # 3. 构造单点 JSON 字典
            point_dict = {
                "name": f"L{layer+1}_C{col+1}",
                "desc": f"第{layer+1}层 第{col+1}根",
                "coords":[
                    round(x, 2), 
                    round(FIXED_Y, 2), 
                    round(current_z, 2), 
                    round(j4, 2)  # 精确计算出来的电机 r 角度
                ],
                "photo": 0,
                "config": elbow_cfg  # 必须写进 JSON，运行时 Controller 才会认
            }
            search_points.append(point_dict)
            
    # === 3. 打印生成的 JSON 字符串 ===
    import json
    print(json.dumps(search_points, indent=4, ensure_ascii=False))

if __name__ == "__main__":
    generate_search_points()
```

运行这段代码，你会得到一个完美的、包含 35 个点的 JSON 数组。里面的每一个 `r` 都是各不相同的，但它们在物理空间上，末端相机的朝向绝对是 100% 平行的！

### ⚠️ 一个极其重要的工业现场警告（翻肘风险）

你的策略中有一环非常危险：
> “每层的5个点，前两个是 elbow_up，后三个是 elbow_down”

在你的搜寻逻辑中，机械臂从 `L1_P2` (Elbow Up) 移动到 `L1_P3` (Elbow Down)。

**这叫做“翻肘（Elbow Flip）”动作。**
机械臂为了从“左手系”变成“右手系”，小臂（J2）必须进行一次**幅度超过 100多度的大范围扫动**。

**如果你直接让上位机做笛卡尔直线插补（MOVL）从 P2 到 P3：**
1.  逆解算法很可能会**报错（无法保持直线）**。
2.  就算能走过去，机械臂的大臂和小臂会像甩鞭子一样向外侧画一个巨大的半圆。**非常容易撞到旁边的料架立柱或安全围栏！**

**解决方案：**
在 P2 到 P3 之间，**必须设置一个安全的过渡点（Via Point）**。
例如，让机械臂先退回到开阔的空地 $\rightarrow$ 在空地完成翻肘动作（切换姿态） $\rightarrow$ 再探入料架去扫 P3。

请务必在现场进行**极慢速 (10% 速度)** 的测试，仔细观察从第 2 个点走向第 3 个点时的机械臂姿态扫动范围！
