


这是一个非常经典的工业视觉难题，在业内被称为**“无限长特征（Infinite Length Feature）定位”**。

由于物料长达 2000mm，远远超出了相机的视野（FOV），相机在画面里只能看到两根平行的直线。相机**根本不知道**自己看到的是物料的头部、中部还是尾部。

因此，**破局的核心原则是：视觉只负责找 X（边缘）和 Z（深度），机械臂的物理位置决定 Y（抓取点）。**

为了确保 图像画面中心、ROI 中心、机械臂 Y 值 和 抓取位置 $P$ 完全对齐，你需要通过**“标定逆推 + 代码锁死”**的组合拳来实现。

以下是具体的操作与实施步骤：

### 第一步：物理示教，确定“黄金抓取 Y 坐标” ($Y_{grasp}$)

不要去算，直接用机械臂去“摸”。

1.  把一根物料端正地放在料架上（保证它平行于基座 Y 轴）。
2.  在手动模式下，移动机械臂，让**夹爪**刚好处于你因为机床干涉而**必须抓取**的那个理想位置 $P$。
3.  此时，读取机械臂的实时基座坐标。假设读取到：`X = 1000, Y = 600, Z = 100`。
4.  **记住这个 `Y = 600`**。这就是你的**黄金抓取 Y 坐标 ($Y_{grasp}$)**。无论是第几层、第几根，最终夹爪下探时，它的 Y 坐标必须是 600。

### 第二步：逆推设定 35 个 `search_points` 的 Y 坐标

因为你的相机和夹爪之间有物理偏差（Offset），所以**拍照时机械臂停的位置，绝对不是抓取时机械臂停的位置**。

为了让相机画面的中心刚好对准物料的“黄金抓取点”，你需要逆推拍照点的 Y 坐标：

*   **公式**：$Y_{search} = Y_{grasp} - \text{Camera_Offset_Y} + \text{Gripper_Offset_Y}$
    *(注：公式的正负取决于你 offset 的定义，简单来说就是让相机镜头物理上移动到 $Y=600$ 的正上方)*。

**实操方法**：
依然是手动控制，把机械臂移开，让**相机镜头的中心**垂直对准刚才物料上的那个抓取点 $P$。
读取此时机械臂的 Y 坐标，假设是 `Y = 680`。

**修改 `config.json`**：
你在 `config.json` 中配置的 35 个 `search_points`，它们的 `X` 坐标各不相同（对应5根料），`Z` 坐标也不同（对应7层），**但是它们的 `Y` 坐标必须全部统一写死为 680！**

```json
"search_points":[
    {"name": "L1_P1", "coords": [1500, 680, 440, -90], "photo": 0},
    {"name": "L1_P2", "coords":[1400, 680, 440, -90], "photo": 0},
    // ... 所有 35 个点的 Y 都必须是 680
]
```

### 第三步：视觉算法的 ROI 居中约束

在你的视觉算法中，你提到：“$x$ 是 roi 的区域中点”。
假设在你的相机坐标系中，图像的 $x$ 轴（左右）对应基座的 $Y$ 轴。

1.  **ROI 必须严格水平居中**：在你的视觉配置 `config.json` (视觉端) 中，ROI 的 X 方向必须关于图像中心对称。
2.  **视觉输出 $0$ 偏移**：因为物料是一根直线，贯穿整个 ROI。视觉算法在计算 $x_c$ (图像坐标) 时，由于你取的是 ROI 中点，它算出来的相对图像中心的偏移量 **必须接近于 0**。
3.  **结果**：视觉算法返回 `[0.0, y_edge, z_depth, angle]`。
    *   $x_c = 0$ 表示在 Y 方向上不做任何视觉补偿。
    *   $y_c = y_{edge}$ 表示在 X 方向上需要补偿边缘距离。

### 第四步：代码级“强制锁死”（终极防线）

即使做了前三步，由于相机安装误差或轻微的倾斜，视觉算法算出来的 $x_c$ 可能不是绝对的 0（比如是个 1.5mm）。如果你把这个 1.5mm 加到基座 Y 坐标上，机械臂每次抓取的位置就会在 Y 方向上左右横跳，最终导致进机床时发生干涉。

**为了绝对安全，我们要在上位机代码中“阉割”掉视觉对 Y 轴的控制权。**

在你的 `handle_process_0x4008D`（抓料动作）中，当你拿到 `target_points_list`（经过 `compute_gripper_target` 计算出的绝对抓取坐标）后，**强制覆盖它的 Y 值**。

```python
    def handle_process_0x4008D(self, process_addr, value):
        # ... (前面的代码：读取视觉数据，生成 target_points_list) ...

        # 【核心修改：强制锁死 Y 坐标】
        # 我们知道理想的抓取 Y 坐标是固定值 (比如 600)
        # 这个值可以写死，也可以从 config.json 里作为一个常量读取
        FIXED_GRASP_Y = 600.0  
        
        for pt in target_points_list:
            # coords 格式为 [X, Y, Z, R]
            # 强行把算出来的 Y 坐标覆盖掉，不允许视觉干扰 Y 轴
            pt["coords"][1] = FIXED_GRASP_Y

        # ... (后续的 move_forward, move_up_down 生成 waypoint 代码不变) ...
        # 因为后续的 L 型避障路径都是基于 target_points_list 计算的，
        # 所以锁死了 target，所有的 waypoint 的 Y 也都会被固定在 600.0。
```

### 总结

这种“部分依赖视觉，部分依赖物理死坐标”的策略在工业上叫 **半约束视觉伺服 (Semi-Constrained Visual Servoing)**。

*   **X 轴（前后）**：依赖相机找边缘（因为物料放在料架上，前后位置会滚动偏移）。
*   **Z 轴（高低）**：依赖相机深度（因为料架有变形、物料有厚度公差）。
*   **Y 轴（左右）**：**绝对不听相机的**，完全由机械臂的编码器走固定坐标（因为机床的卡槽是固定死的，物料在这个方向也是无限长的）。

通过**设置统一的拍照 Y 坐标 + 代码强制覆写目标 Y 坐标**，你就能完美保证每一次夹爪下探，都分毫不差地卡在你想要的那个固定位置 $P$ 上。
